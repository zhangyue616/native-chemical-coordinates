## Inputs and local provenance binding

- Sole H4 input: `<legacy-source-root>/data/derived/lineB/corpus/H4_used.tsv`, expected 10,000 rows. The audit follows the original row order and the original `smiles` bytes; rank, cid, hash and duplicates/anomalies are retained; there must be no deduplication, no canonicalization and no string replacement.
- Old rule source: `chemberta_atom_positions` in `scripts/lineB/models.py` of the adjacent read-only root. The old positions are the ordinals of the tokens in the tokenizer output that are non-special and satisfy `str.isalpha()`; an array is returned only if the RDKit default parse succeeds, the number of letter tokens equals the default RDKit atom count and the total token count does not exceed 512. The runner extracts that function body from the AST of the original source and executes it; it must not import the original model module or rewrite its rule.
- Historical actual encoding path: `chemberta_tokenizer()` always loads `models/chemberta_77m_mlm`, and `_extract_chemberta`/the multi-layer entry points share this one tokenizer for both MLM and MTR. The existence of MTR's own path must not be described as the old code having called two separate tokenizers.
- This run separately loads `models/chemberta_77m_mlm` and `models/chemberta_77m_mtr` from the original root and must not use this root's D/T tokenizer. For each, verify tokenizer.json, tokenizer_config.json, vocab.json, merges.txt, special_tokens_map.json, added_tokens.json, and the config.json that AutoTokenizer needs to determine the type, against the provenance, byte counts and SHA256 in the original `models/download_log.csv`. The historical records point to `resolve/main` of each HF repository; this audit must not fabricate a pinned commit identity.
- The two sets of six tokenizer files must match the historical download digests and be byte-identical to each other before this dual-path audit may be interpreted as equivalent to the historical shared MLM encoding. The two local paths are still run independently per molecule; each row checks that the token IDs, token spelling, offsets and attention/special masks of the local AutoTokenizer encoding and the strict mapper's original encoding agree. Each MTR row is additionally checked against the actual encoding fingerprint of the same MLM row. Any encoding inconsistency is reported only for the affected items; the other tokenizer must not be silently substituted.
- The strict implementation reuses the lexical atom spans, auxiliary source atom-map graph, original-graph signature/complete adjacency verification and token offset attribution of `scripts/revision_20261017/semantic_mapper.py`; the new subclass only injects the respective local tokenizer and provenance identity and does not change the old files. The existing 47/47 synthetic verifications in `results/revision_20261017/mapper/ENGINEERING_CHECKS.json` are reused directly; only a small verification of the local tokenizer adapter is added.
- `prepare` first generates `results/strengthening_20261025/mapping/INPUT_BINDING.json`, saving the actual SHA256, size and mtime of the above inputs/source code/reused evidence/protocol/runner and the verified tokenizer download records, and then generates `AUDIT_LOCK.json`. The per-molecule audit must not be run until the lock and the necessary adapter checks are complete. This binding is part of the protocol; run checks that the binding file, protocol and runner, and the input stat, have not drifted.

## Objects of independent verification and denominators

The primary denominator is the complete 10,000 rows per model, totaling 20,000 molecule-model rows. Duplicate rows remain distinct audit rows. If a run is interrupted, the complete original denominator, the processed count and the unprocessed count are retained; the processed count must not be passed off as the whole. The atom denominator for each model uses the actual atom count of the RDKit graph of the original input string, and must not use the 245,749 from the old first-letter check as an a priori answer; the two values may be compared after completion.

The position object is the zero-based graph atom index of the original exact SMILES under the RDKit `removeHs=False` parse. The strict mapper uses complete lexical atom spans (Cl/Br and a complete bracket atom are each one source atom); an auxiliary parse with source maps binds them to the original graph and verifies atom properties, bonds, stereo information and independent lexical adjacency. The old letter-token order or “the k-th lexical atom” must not by itself be treated as proof of a graph index. It is additionally checked whether the RDKit default parse used by the old rule and the strict graph have the same node/edge indices; if they differ, the historical graph-index control is blocked.

Each strict atom has a comparable position only if the original offset agrees with the decoded source text, the token does not cross atoms, that graph index has exactly one verified element anchor, and the mapper's `element_anchor_position_status=position-aligned`. What is compared is the integer equality of the old `pos[graph_atom_id]` and the independent strict anchor token index, not sameness of first letter, element character frequency or array length.

## Mutually exclusive primary classification and subclassification

Give each row one primary class in the following order, and retain all specific reasons:

1. `hardfail`: input missing/invalid; original tokenizer or provenance binding unavailable; encoding anomaly or incompatibility with the exact old encoding; old position rule returns None (including atom-count and window failures); inconsistent old/strict graph-index contract; or unexpected execution error. The specific failure is recorded, and the row must not be dropped.
2. `ambiguous/unverifiable`: the strict lexical/auxiliary-graph attribution contract does not support this valid input, or the strict element anchor does not exist, is not unique, has an unverifiable offset, crosses atoms, etc., so that there is no complete independent graph-index→position control. This class must not be treated as proven misalignment; candidate differences may be listed separately.
3. `actual_position_disagreement`: the complete comparable relations between the old rule and the independent strict element anchor all hold, and at least one graph index has a different token ordinal. All differing graph indices, old/new positions and tokens/offsets are saved; when a difference is found, its impact is recorded and the work continues as audit only; the scientific sources must not be fixed.
4. `verified_unique_anchor_match`: the above complete comparable relations hold, and the positions of all graph indices are the same. This conclusion concerns only element anchor positions; it does not prove that the model retains complete atomic chemical identity or input syntax.

The reason subtype, strict anchor-error prefix and full-offset-error prefix of `hardfail` and `ambiguous/unverifiable` are all counted completely. Failures must not trigger H4 filtering, model re-encoding, rerunning of the old p, layer changes or supplementary computation of activations.

## Side records kept separate from position

- Atom identity loss: each lost attribute, such as uncovered positions of the complete source atom span, trailing letters of Cl/Br, bracket boundaries, isotopes, formal charges, explicit H and chirality; molecule/atom counts are tallied and the original token identity is retained.
- Offset defects: all original offsets, source-text/decoded mismatches, illegal/overlapping/reversed offsets, atom crossing, etc.; the two fields full offset status and element anchor status are reported. The existing mapper allows a verified non-letter, purely punctuation source-text mismatch that involves no element anchor not to veto a position match on its own; the defect is still recorded as is; offsets must not be fixed and displacements must not be searched for.
- Token encoding consistency, complete encoding fingerprints, atom counts and the relations among the graph indices, duplicate CID/SMILES/whole-row counts and non-atom syntax loss are all saved. Canonical differences must not be used as a new exclusion rule and must not change the input.

## Deliverables, budget and verification

Each model has one full 10,000-row TSV (containing the original input, primary class, subclass reasons, old/strict position arrays and differing graph indices) and one `.jsonl.gz` of complete row-by-row mapping detail; in addition there are `SUMMARY.json`, `ADAPTER_CHECKS.json`, the input binding/lock and an independent `CPU_LEDGER.json`/events. Anomaly details retain the original input and must not be silently skipped. Centralized final-stage acceptance is responsible for checking the total denominator/class sums/graph indices and difference sampling, and reuses the 47 items of old engineering evidence; the executor must not repeat the full old test chain.

0 network, 0 model load/forward, 0 new training/re-encoding/fitting/bootstrap; only local Python and tokenizers are used, and access to weight contents is prohibited. CPU is accumulated per call with time.process_time() into an independent ledger, with a hard cap of 1,800 CPU seconds; at 1,760 seconds the runner reserves the remainder for wrap-up and saves partial output. Insufficient budget must not shrink the denominator or lower the standards.
