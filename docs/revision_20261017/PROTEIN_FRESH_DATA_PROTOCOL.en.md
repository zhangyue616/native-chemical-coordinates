# Long-protein fresh source gate: fixed source, full-raw old-pool exclusion, and the 1304-group gate

> English reader translation of [`PROTEIN_FRESH_DATA_PROTOCOL.md`](PROTEIN_FRESH_DATA_PROTOCOL.md), added for this public release. It is not a study record: the Chinese file is the record of this protocol and governs if the two differ.

2026-10-17. This contract authorizes only the offline implementation, limited synthetic checks, and supplementing the old exact-sequence key. Real HTTP must first have a `SOURCE_DATA_GO` data lock issued by the research operator. There is no PLM load/forward, activation, prediction, or confirmation p; the old P1–P5 and the existing D artifacts are frozen. Judgment: the engineering contract is verifiable (high); the sufficiency of 1304 qualified fresh groups is unknown; the actual precision on long T is unknown.

## 1. Fixed source and request budget

The sole source is `https://rest.uniprot.org/uniprotkb/search`; the sole query is `(reviewed:true) AND (length:[257 TO 512]) AND (database:pdb)`; `sort=accession asc`, JSON, size500. From the official starting point, following each official next, change only the metadata-stage fields to `accession,sequence,length,xref_pfam,xref_pdb,ft_helix,ft_strand`, to obtain the complete sequences, Pfam/PDB, and exact Helix/Beta-strand features required for old P5 qualification.

The complete source must be exactly the 13658 records and 28 successful pages (27×500+158) of the exhausted metadata snapshot; release/date must be `2026_03` / `02-September-2026`, and each page must have `x-total-results=13658`. The accession order of each page must be exactly the same as the corresponding slice of `metadata_projection.jsonl`, and the final set and order must be exactly the same; page 28 must end with no next, and each earlier page must have a next. A repeated URL, drift in fields/sort/query/size, or a change in release/total/IDs/count each means an immediate stop; partial must not be treated as insufficient source, and partial qualification conclusions must not be used.

Each URL has at most 3 total attempts (the first attempt plus at most 2 transient retries of the same URL); only 429/500/502/503/504 or classified timeout/connection/DNS transient errors may be retried, at intervals of 1 second and then 2 seconds. 45-second request timeout. URLs must be HTTPS on the sole official search path; redirects or external domains are not allowed. No batch concurrency, no additional query, no change of source/length/unreviewed, and no automatic full-pipeline resume; on failure, keep the raw records already received and the safe receipts, then hand over to the research operator. A successful raw response is saved and entered in the source ledger immediately, and integrity checks come after that.

The existing network path is inherited; proxy/VPN settings must not be enumerated, modified, or output; the system network, TUN, DNS, or routing must not be changed. Receipts store only the public official request URL, the allowed source headers, and status/exception categories; they must not store any HTTP error body or exception text, to avoid accidentally retaining proxy/authentication secrets; Cookie/token/local proxy information must not be output.

## 2. Full-raw union graph and the D grouping gate

Reuse the 3967 old supernodes of the metadata `OLD_POOL_GRAPH.json`, which already represent all of the old 16896 raw records (P1 512+P2/P3/P4/P5 4096 each) and the old internal transitive closure over ID/complete sequence/any known Pfam. That file did not store a sequence key, so for this new necessary key only, the ID/sequence/Pfam of these 16896 old raw records are read again offline, once each, verified against old source size/mtime/count and the supernode projection, and saved as `SHA256(complete sequence UTF-8)→old_component_index` in `OLD_EXACT_SEQUENCE_INDEX.json`. The old graph must not be rebuilt, and the old statistics or the full SHA of old raw files must not be recomputed; the existing source identity/acceptance is reused. SHA here is a necessary exact-sequence join key, not a full-directory re-verification.

The download must be complete and the source verification must pass before all 13658 new raw nodes are added to the old supernodes. Take the complete transitive closure of the union graph over identical accession, the SHA of the complete sequence, and any known Pfam. Records with an invalid sequence, no label, no PDB, or no Pfam, and records that will be filtered out, are all in the graph; a no-Pfam node can still connect via ID or sequence. A missing sequence has no such key but the other keys are still kept; invalid raw records must not be deleted early. First build the full graph and mark all connected components touching an old supernode, then do the qualification screening. Known-graph isolation does not guarantee remote-homology independence or the absence of pretraining overlap.

The old 432 selected pairs must join exactly to the current `OLD_SELECTED_UNION_GROUPS.json` by `(origin,id)`. A new root is named `old-union-{index+1:06d}` from the smallest index of the old supernodes it connects to; the mapping and group identity must be exactly the same as the existing D421 groups (hash folds depend on group identity). If a further merge occurs or group identity is affected, output `OLD_SELECTED_FINAL_GROUPS.json` and `D_GROUPS_CHANGED_QUALIFICATION_HELD`, **qualification screening is suspended immediately**, and the case first goes to the research operator for a targeted update of the affected D groups/folds and precision. It must not be claimed any further that the original N1304 precision contract applies. The current implementation has no authority for automatic D refitting or for modifying precision.

The graph outputs `components.jsonl`, the 13658-line `raw_group_join.jsonl`, `GRAPH_RESULT.json`, and the 432-item final old selected mapping. Each complete raw record has exactly one group; all new connected components, members, known Pfam, and flags for touching the old pool are saved. The key of a pure-fresh connected component is `acc:<ids>` after sorting all its members by accession.

## 3. Old P5 qualification and pair rules reused unchanged

Directly import, read-only, `labels_and_pair`, `exact_interval`, `pdb_crossrefs`, `parse_chains` and their native helper functions from `scripts/prepare_pilot5a_data.py`; the structural-label selector must not be copied or rewritten. SEED is set to the fixed new salt `protein-long-transfer-20261017-v1` only in a separately loaded module instance; the original file must not be written. The only change is the outer length, from 64–256 to 257–512; the requirements of canonical 20AA, source length consistent with actual length, and reviewed Swiss-Prot are unchanged.

First exclude each entire component touching the old pool, then require the valid long sequence above and a PDB crossref, and then call the native selector. All original P5 rules are retained: Helix/Beta strand only; positions must be EXACT integer intervals on the canonical accession and in the valid range; HELIX/STRAND overlapping positions are excluded as conflicts; the center must be A and must have the complete ±7; feature evidence must have `source=PDB`, a valid `ECO:\d{7}`, and a matching entry PDB crossref; experimental methods only from the original set X-ray/NMR/EM/Neutron/Electron diffraction; there must be an explicitly parseable non-`-` chain and UniProt coordinate coverage, whose intersection with the feature covers the center. ±15 may be incomplete and will later be encoded by PAD; the same PDB or the same chain is not mandatory, and no additional condition on the distance between the two sites or on window non-overlap is added. This is UniProt coverage evidence; no new PDB atomic mapping is claimed.

Multiple pieces of evidence for each valid site are resolved by taking the minimum hash of the old tuple and the new salt. All valid HELIX-A×STRAND-A combinations with different q are traversed, and the unique pair is taken by the old pair hash/tuple. The exact hash envelope stays as in P5:

- evidence: `SHA256("pilot5a-evidence:{accession}:{q}:{label}:{pdb}:{chain}:{start}:{end}:{eco}:{salt}")`, ties broken by the old `evidence_tuple`.
- pair: `SHA256("pilot5a-pair:{accession}:{hq}:{sq}:{hpdb}:{hchain}:{spdb}:{schain}:{salt}")`, ties broken by `(accession,hq,sq,hpdb,hchain,spdb,schain)`.
- Members of the same connected component: minimum `SHA256("pilot5a-protein:{accession}:{salt}")`, ties broken by accession. At most 1 protein/pair per connected component.
- Connected components: `SHA256("pilot5a-component:{component_key}:{salt}")` ascending, ties broken by component_key.

Sorting must not be by label effect, activation, prediction, or p. Pair output is a/b in ascending q order, `y_a=1{a is HELIX}`; a is not guaranteed to be HELIX. Every selection salt/hash/tie is fixed before the new source labels and model outputs.

## 4. Sufficiency gate, sealed inputs, and failure

The sole target of the existing D precision plan is 1304 final known fresh connected components, cap1536; this gate must not lower it to 512, expand the pool, or add members according to the T effect. Only when the D grouping is completely unchanged and valid connected components ≥1304 are the first 1304 taken in the predetermined connected-component order; the rest are marked unused and are not a reserve for effect-based sample top-up. Valid connected components <1304 means `FRESH_DATA_INSUFFICIENT`: no partial formal T cohort is written and no model is run. The 2074 metadata connected-component upper bound is never regarded as actual sufficiency.

On passing, write `proteins.jsonl` (1304) and `SEALED_FRESH_CASES.json` (2608 cases, 1304 canonical pairs, containing the complete sequence/q/token q+1/label/group and pairing), status `INPUTS_SEALED_NO_MODEL_OUTPUT`. Structural labels are read only for pre-lock eligibility and the fixed pair selection; no activations, predictions, tests, or PLM outputs are included. This input set is for the research operator's later separate `T_OUTPUT_LOCK`; this data lock does not release T output. If the sufficiency gate is not passed, keep the complete funnel/evidence and the unused candidate list; this must not be called completed confirmation.

Uniformly report raw→exclusion of components touching the old pool→canonical reviewed long sequences→PDB crossref→A sites of both classes/valid pair records→connected-component representatives→selected; save the retained count at each step and the non-mutually-exclusive exclusion reasons, the number of valid pair combinations, the number of connected components, the raw/selected length distributions, the feature/site/evidence exclusions, and the complete groupID join count. Different exclusion reasons may overlap; reasons must not be summed and passed off as raw counts.

Write only the new scripts/tests, this protocol, and `data/revision_20261017/protein_fresh/`. The existing Python standard library; no new dependencies or model libraries.
