# Protein metadata feasibility prerequisite gate

> English reader translation of [`PROTEIN_METADATA_PROTOCOL.md`](PROTEIN_METADATA_PROTOCOL.md), added for this public release. It is not a study record: the Chinese file is the record of this protocol and governs if the two differ.

2026-10-17. The scope is one authorized metadata-only gate; **no new scientific route, T, model run, or confirmation test is authorized**. The script is `scripts/revision_20261017/protein_metadata_gate.py`, and all new data and receipts are written only to `data/revision_20261017/protein_metadata/`. The old data/scripts/results are read-only, and old research data must not be read.

## Fixed source and budget

Sole endpoint: `https://rest.uniprot.org/uniprotkb/search`. The query is fixed as `(reviewed:true) AND (length:[257 TO 512]) AND (database:pdb)`; `sort=accession asc`; `format=json`; `fields=accession,length,xref_pfam`. `sequence.value`, HELIX/STRAND/other structural labels, `xref_pdb`/PDB mappings, or activations must not be requested. The source release is fixed as `2026_03` / `02-September-2026`; a different or missing value means `SOURCE_DRIFT`: keep the actual response and stop; a new release must not be accepted.

`X-Total-Results` in the first API response is the official query raw total, **not the usable N**. This run takes, from the official starting point in ascending accession order, at most the first **16,384 raw / 33 successful HTTP pages** or until official exhaustion, stopping at whichever comes first. The initial page has size=500; after that, only the official `next` cursor is followed, with size changed to `min(500, 16384-received raw)`; other parameters, including query, fields, sort, and cursor, are unchanged. The full quota is 32×500+384. Duplicate, old-connected, invalid, and no-Pfam records all count toward the raw budget; the pool must not be topped up, the query/sort/source must not be changed, and there must be no expansion to >512/unreviewed.

Only the fixed official HTTPS endpoint is accepted, and redirects must not be followed; mismatched next URL parameters, a repeated cursor/URL, descending accession, pagination/total anomalies, or exceeding the quota means an immediate stop. Repeated accessions may be entered in the ledger and used for graph bridging. Each URL has at most 3 attempts for temporary network errors/HTTP 429, 500, 502, 503, 504; a non-temporary error means an immediate stop. A JSON parse failure after HTTP 200 keeps the raw and stops; a successful response must not be retried. The existing proxy environment is used only as the runtime default; its configuration must not be read, printed, or changed. For exceptions, only the safe type and HTTP status are recorded; exception bodies that may contain credentials must not be recorded.

## Old full-raw union graph

The old pool is fixed as all 512 of `data/proteins.jsonl`, plus all 4096 raw records bound by each of `data/pilot2/http_provenance.json`, `data/pilot3a/http_provenance.json`, `data/pilot4a/http_provenance.json`, and `data/pilot5a/http_provenance.json`, a total of **16,896**, not limited to the old selected; biologically invalid/unlabeled records likewise retain their bridging role. Only old accession, complete sequence, and all known Pfam are projected; old structural labels or activations must not be used. The P5 old lock/asset manifest and the identity declared by each receipt are reused, and the record count, schema, bytes, and on-site mtime are verified; **the old raw SHA must not be fully recomputed**, and re-completion of the old asset acceptance must not be claimed.

First perform transitive merging on all old raw nodes by identical ID, complete sequence, and any shared Pfam; then losslessly compress the old connected components into supernodes and save `OLD_POOL_GRAPH.json`, containing all IDs/Pfam of each connected component, the raw member count, and the old identity entry points; old sequences must not be copied. Subsequent new metadata merges into these supernodes only by ID/Pfam, which is equivalent to building the union graph directly on all 16,896 old nodes. If any transitive connection of a new node touches an old supernode, the entire connected component is excluded; Pfam bridges carried by repeated IDs must not be discarded.

Separately, project only the selected 176/128/128 IDs and old component keys from the old P3/P4/P5 `proteins.jsonl`, 432 pairs in total; their structural labels, sites, or model outputs must not be read. Report whether each round's old connected-component keys merge in the full old-raw union graph, to provide the currently known group mapping for later unified CV; if new metadata further bridges old connected components, update the mapping and the merge count again. The pre-HTTP mapping is saved in `OLD_SELECTED_UNION_GROUPS_PRE_HTTP.json`, and after traversal in `OLD_SELECTED_UNION_GROUPS.json`; these are all old D identity groupings, and no CV or fitting has been run.

New records project only `accession/sequence.length/Pfam IDs`, saved line by line in `metadata_projection.jsonl`; it is a projection of all metadata seen, **not a candidate T or T selection**. Invalid records still bridge and consume budget; new no-Pfam raw records are counted separately. If a response unexpectedly contains new sequence.value, features, PDB, or other unrequested content, the raw original text is kept only as a source receipt and the field paths/counts are recorded; its values must not be used for exclusion, label judgment, mapping, or any statistics. The default `entryType` is treated only as implicit API metadata and must not be used for additional filtering.

## Upper bound and determination

After the frozen traversal is completed, the number of new connected components remaining after old-pool exclusion (including connected components with only invalid metadata) is a conservative upper bound. The missing new exact-sequence edges may merge connected components or connect them to the old graph; subsequent structural labels, PDB mapping, center-A/valid pairing, and other predetermined quality gates can also only further reduce the number. Therefore this number must not be written as qualified fresh T, independent N, or the scientific route already being feasible. Known Pfam/ID isolation also does not prove remote-homology independence or the absence of pretraining overlap.

Output the official total, actual raw, unique accessions, duplicates/invalid, new Pfam and no-Pfam, direct/transitive exclusions of old connections, and the remaining connected-component upper bound; answer separately, for 512 and for 1536, whether it is impossible even at the upper bound. If the upper bound after completion is <512, this fixed-budget data route is rejected; if the upper bound≥threshold, this means only that the metadata upper bound has not yet excluded the corresponding threshold, and does not pass the new T gate. If fetching fails/drifts, report only what was actually seen and the failure; a partial upper bound must not be used to reject an uncompleted route; no additional query is opened in this run.

## Lock and execution

1. Run `.venv/Scripts/python.exe scripts/revision_20261017/protein_metadata_gate.py prepare`: HTTP=0. Run limited synthetic bridging/budget/field-ignoring checks, read the old ID/sequence/Pfam once to build the old graph, and write `SYNTHETIC_CHECKS.json`, `OLD_POOL_GRAPH.json`, `DATA_RULE_INPUTS.json`. The last of these binds this protocol, the script, the old graph SHA, and the old source identity/stat; no model or new science is run.
2. Deliver `FINAL_READY` to the research operator. The research operator completes the lock; the metadata executor must keep all HTTP=0 until it receives the research operator's explicit `DATA_RULE_LOCK` reply.
3. The research operator writes `DATA_RULE_LOCK.json` in the same directory, with the minimal structure `{"status":"DATA_RULE_LOCK","frozen_utc":"current ISO time with time zone","inputs_sha256":"SHA256 of DATA_RULE_INPUTS.json","http_requests_before_lock":0}`. The research operator may add authorization/boundary text but must not modify the prepared inputs. The script verifies that the lock time, inputs, script/protocol/old graph identity, and old source stat have not drifted.
4. After receiving the lock, run `.venv/Scripts/python.exe scripts/revision_20261017/protein_metadata_gate.py fetch` once. At run time the compressed old graph is reused and the old raw is not fully read again; only one frozen GET pagination traversal is done. If an HTTP receipt/raw already exists, re-execution is refused, with no automatic resume/requery.
5. Save raw and the safe HTTP status/time/necessary response headers/official next, `http_provenance.json`, and `METADATA_GATE_RESULT.json`. Each attempt and each successful response is written to disk promptly; on failure the actual receipt is left. The result contains readonly/scope counts: new sequence/label/mapping use 0, activation reads 0, model/forward/fit/T selection/old statistics reruns 0.

This subtask performs only this prerequisite gate. The final acceptance of the major stage is the responsibility of the research operator, reusing these limited synthetic checks and the actual receipts, without repeating the old science or the entire asset inspection.
